**Delivery spec**: S1 seam repair, Wave 2 (six parallel delivery specs)
**Owner**: triga-engine campaign → `delivery` → `factory`
**Seam**: D — `scene.fab` store/query → nested package `src/scene/{node,store,query}.fab` + map-only `src/scene.fab` facade
**Timing window**: Stage 5→7 corridor, **before 80 Stage 7** (culling/picking grows the query side). Must NOT land during 80 Stages 4–5 without coordination, nor during Stage 7. 80 Stage 4 is in flight (2026-08-01) while this spec is drafted; implementation lands in the corridor.
**Frozen by**: S0 checkpoint report §1.2/§2/§3/§8 — `docs/factory/triga-engine/checkpoint/report.md`; consumer/pin evidence: `checkpoint/T-B-seam-consumers.md` (Seam D table); format: `docs/factory/triga-threejs-80/01-math-transform-delivery.md`.

## Goal

Split `src/scene.fab` (~930 lines) into the nested package `src/scene/{node,store,query}.fab` plus a `src/scene.fab` map-only facade, as a **pure relocation with unchanged interface names and owners**, landing before 80 Stage 7. The split keeps the two pinned scene fixtures (`exempla/triga-scene-store.fab`, `exempla/triga-scene-store-empty.fab`) at import-line churn only, keeps the Stage 2 generated-Rust acceptance, the direct Radix check, and the generated-Rust run (all wired into `scripta/check-compile`) meaningful, and restores the scene-side compile gate by coordinating the faber generated-code lowering fix — never by weakening fixtures. DS-D additionally **proves the nested-package tooling check first** for the whole S1 wave (report §8 names it the precondition gate of every S1 split).

## Invariant

**PURE RELOCATION**: every public genus name, discretio case name, receiver-method name, free-function name, and signature stays byte-identical. Consumers of `triga:scene/*` see the same interface; only import specifiers and qualifiers change. No renames, no behavior change, no fixture assertion change, no workaround of the compile-gate regression. `check-compile` green is the gate.

### Exact leaf → genus map

**`src/scene/node.fab`** (`triga:scene/node`; imports `triga:math`, `triga:resource`)

- `discretio SceneNodeKind` — `SceneGroup`, `SceneMesh`, `SceneCamera`, `SceneLight`

**`src/scene/store.fab`** (`triga:scene/store`; imports `triga:math`, `triga:resource`, `triga:scene/node`)

- `genus SceneHandle` — `index`, `generation`
- `genus SceneStore` — field `slots`; **store-owned receiver methods, owner unchanged**: `insere`, `continet`, `cape`, `adiunge`, `seiunge`, `detrahe`, `inveni`, `pone_visibile`, `pone_matrix_localem`, `matrix_mundi_mesh`, `renova_mundum`; internal helpers co-located: `_reple`, `_sine_liberis`, `_circuitum_faceret`, `_nota_mundum_sordidum`, `_renova_mundum_nodum`, `_traversal_continet`, and the five `_traverse*`/`_visibile_*` preorder skeletons
- **query-facing receiver methods, still on `SceneStore` (owner unchanged)**: `traverse`, `traverse_visibilia`, `traverse_visibilia_rete`, `efficax_visibile`
- **free constructors / utilities**: `scene_store()`, `scene_node()`, `scene_group()`, `scene_mesh()`, `scene_camera()`, `scene_light()`, `scene_handle_equals()`

> **Traversal-method placement note.** The frozen content map assigns the traversal machinery to `query`, and the query leaf is its semantic home (value types + `visibilia` entry point). But the public traversal methods are receiver methods on `SceneStore`, and Faber declares receiver methods inside the receiver genus's module (single-declaration semantics; no method-on-foreign-genus feature is present in the codebase — sibling nested package `norma:caelum/*` declares methods only inside each genus's own block). Moving the `traverse*`/`efficax_visibile` declarations into `query.fab` would also force a `store ↔ query` cycle because `inveni` (store-owned, frozen) calls `_traverse_preorder`. **Default branch therefore: all `SceneStore` methods stay physically declared in `store.fab`; `query` owns the traversal/query value types and the `visibilia` entry point.** The Stage 1 tooling probe re-checks cross-leaf method declaration; if (unexpectedly) legal with no cycle, method declarations may host in `query.fab`. Both branches keep every public name, receiver, and signature identical, so the gate does not depend on the choice.

**`src/scene/query.fab`** (`triga:scene/query`; imports `triga:math`, `triga:resource`, `triga:scene/node`, `triga:scene/store`)

- `genus SceneTraversal`, `genus SceneCount`, `genus SceneMeshResources`, `genus SceneMeshTransformPayload`, `genus SceneMeshDrawPacket`, `genus SceneVisibleMeshDrawBatchFacts`, `genus SceneVisibleMeshResourceFacts`, `genus SceneMeshResourceTraversal`
- `genus VisibiliaRetium` — methods `numerus()`, `geometriae()`, `materiae()`, `octeta()`, `ductus()` (api-shape-policy §4 projection rule unchanged)
- free function `visibilia(de SceneStore store, de SceneHandle radix, de math.Matrix4 visio_proiectio) → VisibiliaRetium ∪ nihil`

**`src/scene.fab`** (facade) — map-only; no genera, no functions.
